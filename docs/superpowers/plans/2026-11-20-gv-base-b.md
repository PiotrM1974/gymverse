# GV-BASE-B Implementation Plan

**Goal:** Repair workout completion, durable saves and drafts, atomic JSON imports, and service worker cache updates without migrating data or implementing Web Push.

**Architecture:** Keep existing application state and DOM in `index.html`; extract only deterministic completion, draft, and storage-transaction helpers into a small testable `src/gv-base-b.js` loaded before the existing inline application. Keep export format v4 and legacy records unchanged. Constrain service worker cache lifecycle to the `gymverse-` namespace and let updates wait until old clients close.

**Tech Stack:** Existing vanilla JavaScript, Vitest, Playwright, Node 26.

**Spec:** `docs/spec/GymVerse_2_0_MASTER_PROMPT_v2_8.md` §0, §2, §14.2; task `docs/tasks/GV-BASE-B.md`.

**BASE_SHA:** `061b3bc8f7b02634b98792fbb89f841bc60ca96f` (`main` and `origin/main` at start).

## Global Constraints

- Use only synthetic fixtures and browser storage created by tests.
- Preserve existing v4 JSON import/export compatibility; do not start GV-DATA or change the master snapshot.
- Keep service worker caches limited to the `gymverse-` prefix; do not force active clients onto an update.
- Never clear data on a failed save; verify writes by read-back and retain active state on error.
- Keep all E2E servers bound to `127.0.0.1`; do not stop unknown listeners.
- Do not merge or deploy.

## Review Focus

- Duplicate or out-of-range active sets must not inflate completion counts; pin with completion-helper unit tests.
- A mid-transaction quota failure must restore prior stored values and leave in-memory imports untouched; pin with storage unit tests and E2E.
- Draft strings such as partial decimals must survive refresh and remain uncommitted; pin with E2E.
- Import confirmation cancellation and malformed input must leave all state unchanged; pin with synthetic v4 E2E cases.
- Service worker activation must preserve non-GymVerse caches and existing offline image paths; pin with a VM lifecycle test.

## Files

- Modify: `index.html` for progress confirmation, verified save flow, drafts, and staged imports.
- Create: `src/gv-base-b.js` for pure progress, draft, and transactional-storage helpers.
- Modify: `sw.js` for namespaced cache cleanup, deferred activation, and app-local cache reads.
- Modify: `playwright.config.js` to permit a test-only loopback port override.
- Modify: `tests/e2e/workout.spec.js` for synthetic browser regressions.
- Create: `tests/unit/base-b.test.js` and `tests/unit/service-worker.test.js`.

## Tasks

1. Add failing tests for completion math, transactional storage, drafts, import safety, and SW cache behavior; observe expected failures.
2. Implement and verify completion checks for both finish paths, real `X/Y` progress, separate excess count, and confirmed zero-set discard.
3. Implement verified storage transactions, keep active state until completion persistence succeeds, and expose an emergency v4 JSON download on failure.
4. Implement namespaced persistent drafts, restore/label/clear rules, and regression E2E for refresh and confirmation flows.
5. Make imports prepare all next state without mutation, then write atomically and publish in-memory changes only after verified storage success.
6. Restrict SW cache deletion and reads to GymVerse caches; defer worker takeover and verify offline fallback and legacy asset URLs.
7. Run `npm test`, Edge Chromium E2E, WebKit if available; audit the final diff and all protected production assets.
