## Wynik lokalny — do oceny

Dodano `readAssignedProgram` i `assignProgram` w istniejącym module programów; `deleteProgram` nadal usuwa przypisanie przy usuwaniu jego programu. UI pokazuje przypisanie, bibliotekę programów i samodzielnych dni, podgląd programu i każdego dnia. Przypisanie oraz wyczyszczenie to osobna akcja; podgląd nie zapisuje i nie rozpoczyna treningu. Przed zapisem porównywany jest aktywny profil i migawka rejestru oraz planów, po zapisie wykonywany jest odczyt kontrolny. Zapis dotyczy jednego rekordu rejestru; nie zmienia historii, aktywnej sesji, RIR ani draftów. Zmiana przypisanego programu wymaga potwierdzenia.

Smart ZIP: lokalne jawne ID/null wygrywa i przy różnej wartości źródłowej zgłasza konflikt; gdy lokalne metadane nie istnieją, przypisanie z kopii przyjmowane jest po przyjęciu identycznej grupy oraz wszystkich dni. Nowy profil zachowuje swój wybór. ZIP v5 pozostaje bez zmiany formatu, JSON v4 nie tworzy przypisania. Kolizje mają czytelny opis.

`integrityUncertain` przy przypisaniu lub wykrytym błędzie importu / rollbacku powoduje ostrzeżenie i blokadę zapisu w bieżącej sesji. Można przygotować ZIP z dostępnego snapshotu po walidacji struktury i zawartości przez istniejące mechanizmy; komunikat nie gwarantuje kompletności po awarii. Awaryjny JSON v4 jest oznaczony jako niekompletny dla profili i programów. Blokada nie jest trwała po zamknięciu/reload, a pełna detekcja awarii wszystkich starych ścieżek zapisu nie została dowiedziona. Między ostatnim sprawdzeniem localStorage i zapisem nie ma globalnej blokady obejmującej wszystkie inne karty; wyścig w wielu kartach pozostaje ryzykiem.

Świeżo: `npm test` 167/167; Edge 24/24 zestawu 6.3B/6.3C oraz 3/3 dodatkowych testów aktualności i ekranu; regresja Edge 36/36 profili, starszych celów i kopii. Syntetyczne dane: eksport i restore ZIP przez UI, import i powtórzenie, konflikt, dwa profile, aktywna sesja/RIR/drafty, odmowa zapisu, symulowany nieskuteczny rollback i ZIP z dostępnych danych. ## Końcowe zabezpieczenie 6.3C — 24.11.2026

Dwie aktualne karty używają wspólnej wyłącznej blokady Web Locks `gymnastika-program-assignment` obejmującej ponowne sprawdzenie i zapis przypisania. Jeśli Web Locks nie są dostępne, przypisanie jest bezpiecznie wstrzymane. Nieaktualny widok pokazuje komunikat i przycisk bez-zapisowego odświeżenia, z ochroną aktywnej sesji przy zmianie dni/profilu. W IndexedDB `refreshSnapshot` odczytuje rzeczywistą migawkę, a zapis porównuje wersję utrwaloną razem z migawką, zamiast zmiennej rewizji zmienianej przez komunikat w tle. Konflikt IDB jest odrzucany bez automatycznego traktowania go jako uszkodzenia i może prowadzić do odświeżenia. PWA cache v42.

Zakres: serializacja dotyczy współpracujących, aktualnych kart wykonujących operacje przypisania. Starsze otwarte wersje i inne ścieżki niekorzystające z tej samej blokady nie są objęte pełną gwarancją; nie utożsamiać BroadcastChannel ze wzajemnym wykluczaniem. Gdy przeglądarka nie udostępnia Web Locks, użytkownik nie może zmieniać przypisania. Nie twierdzić, że wszystkie zapisy całej aplikacji są zabezpieczone.

`integrityUncertain` nadal blokuje wykryte niebezpieczne zapisy w bieżącej sesji, oferuje walidowany strukturalnie ZIP z dostępnego stanu i niekompletny JSON v4. Ostrzeżenie wyjaśnia, że może zniknąć po ponownym uruchomieniu i zaleca zamknięcie innych kart oraz odtworzenie wcześniejszej zweryfikowanej kopii. Test potwierdził, że obecnie po reload ostrzeżenie nie przetrwa; nie ma trwałej gwarancji przy awarii magazynu. Odtworzenie wcześniejszego syntetycznego ZIP po symulowanym nieudanym rollbacku przeszło w obu silnikach. Wykrywanie błędów wszystkich starszych ścieżek całej aplikacji pozostaje osobnym zakresem.

Edge offline przebadany; WebKit offline pominięty zgodnie z wcześniejszym znanym problemem środowiska. Fizyczny iPhone/Safari i autentyczny eksport historyczny nadal niezweryfikowane.
